# XR-2000 安全白皮书

## 1. 安全设计原则

XR-2000 遵循三条设计原则：默认最小权限、全程可审计、密钥不落盘。
所有管理接口默认只监听本地回环地址，如需远程管理必须显式开启并配置 TLS。

## 2. 认证与授权

系统支持三种认证方式：本地账号密码、LDAP 对接、以及 OIDC 单点登录。
默认启用的是本地账号密码。生产环境建议切换到 OIDC 并强制开启多因素认证。

会话令牌默认有效期 8 小时，空闲 30 分钟自动失效。令牌使用 JWT 格式，
签名算法固定为 RS256，不接受客户端指定算法（防止 alg=none 攻击）。

管理员账号连续 5 次密码错误会被锁定 15 分钟。锁定阈值可以通过
`security.login.max_attempts` 调整，但不建议设为大于 10。

## 3. 传输安全

管理 API 支持 TLS 1.2 和 TLS 1.3，明确禁用 TLS 1.0/1.1 以及所有已知不安全的密码套件。
自签证书在生产环境不被接受，必须使用受信任 CA 签发的证书。

上行与下行业务流量支持 IPsec 与 WireGuard 两种加密隧道。
WireGuard 性能更好（实测吞吐比 IPsec 高约 40%），但不支持硬件加速；
如果需要国密算法，只能选 IPsec，因为 WireGuard 目前不支持 SM 系列算法。

## 4. 数据安全

XR-2000 默认不存储业务数据。以下三类内容会落盘：运行日志、抓包文件、本地规则缓存。
日志中的敏感字段（密码、令牌、身份证号）会自动脱敏，脱敏规则可以通过
`security.mask.patterns` 自定义。

抓包文件包含明文流量，默认保留 7 天且只允许管理员下载。
如果开启了全量抓包，请务必确认存储卷已加密，否则等于把用户流量明文留在磁盘上。

## 5. 漏洞管理

安全补丁的发布节奏为每月一次，紧急漏洞在确认后 72 小时内发布临时补丁。
所有补丁都附带 CVE 编号与影响范围说明。

可以在控制台的「安全公告」页面订阅补丁通知，或通过
`GET /api/v1/security/advisories` 接口拉取公告列表。

## 6. 合规性

XR-2000 已通过等保三级测评，支持生成符合要求的审计报告。
审计日志默认保留 180 天，这个期限不可通过配置缩短，以满足合规要求。
