# XR-2000 常见问题

## 运维类

### 日志里大量出现 E1042，该怎么办？

E1042 是上游连接超时。先不要急着调大 upstream_timeout，按顺序排查：

1. `xros-cli upstream health` 确认上游服务本身是否健康。
2. 看超时值是偶发还是持续。偶发（每小时少于 5 次）属于网络抖动，可以忽略。
3. 确认 upstream_timeout 是否大于上游的 P99 延迟。经验值是设为 P99 的 2 到 3 倍。
4. 如果上游正常，检查中间网络是否有丢包或 MTU 不匹配。

盲目调大超时时间会掩盖真实的上游问题，还可能拖长请求堆积。

### 如何调整上游超时时间？

有两种方式。改配置文件 `/etc/xros/gateway.yaml` 里的 `upstream_timeout`（单位秒，默认 30），
然后执行 `xros-cli reload` 热加载；或者用 REST API 在线修改：

```bash
curl -X PATCH http://localhost:8080/api/v1/config \
  -H "Content-Type: application/json" \
  -d '{"upstream_timeout": 60}'
```

REST API 的修改立即生效且不需要重启进程，但不会写入配置文件，重启后会丢失。

### 支持集群部署吗？最少几个节点？

支持。集群依赖 Redis 存放共享状态，最小生产规模建议 3 个节点，可以容忍 1 个节点故障。
所有节点的授权码必须一致，时钟偏差不能超过 5 秒。

### 容器重启后配置会丢失吗？

取决于修改方式。通过配置文件或环境变量设置的配置不会丢；
通过 REST API 在线修改的配置只存在于内存中，容器重启后会恢复成配置文件里的值。
生产环境建议把要长期保留的改动写回配置文件。

### 服务启动失败，提示 License 无效怎么办？

先检查三点：授权码有没有填错、License 是否已过期、服务器系统时钟是否准确。
License 校验依赖系统时间，时钟偏差过大（超过 24 小时）会被判定为无效。
可以用 `date` 命令确认时间，用 `xros-cli license info` 查看 License 的到期时间。

## 容量与性能类

### 并发连接数上不去，一直是 3000 左右？

检查是否启用了深度包检测（dpi_enabled）。开启 DPI 后每个连接的内存开销显著上升，
官方建议此时把并发连接数控制在 3000 以内。如果确实需要更高的并发，请关闭 DPI 或升级硬件。

### 内存占用随时间持续增长，是内存泄漏吗？

不一定是。先看是不是连接池或缓存自然增长到稳态。如果内存持续增长且不回落，
用 `xros-cli diag memory --top 20` 查看占用最高的模块。
如果是 E5003（上游连接池耗尽）同时出现，很可能是连接泄漏，需要检查上游服务是否正确关闭了连接。

## 管理类

### 如何查看当前版本？

执行 `xros-cli version`，或访问 `GET /api/v1/version`。
版本号格式为 `主版本.次版本.修订号`，例如 3.2.1。

### 日志默认保留多久？可以改吗？

默认保留 30 天。如果 log_level 设为 debug，日志体积可能增长 10 倍以上，建议同步缩短保留期。
用 `xros-cli storage usage` 查看占用，`xros-cli storage rotate` 手动触发轮转。

### 忘记 Web 控制台管理员密码怎么办？

在服务器上执行 `xros-cli admin reset-password --user admin`，
该命令会生成一个一次性临时密码并输出到终端，首次登录后必须修改。
