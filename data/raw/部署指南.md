# XR-2000 部署指南

## 1. 环境要求

部署 XR-2000 控制平面之前，请确认目标主机满足以下条件：

| 项目 | 最低要求 | 推荐配置 |
| --- | --- | --- |
| CPU | 4 核 | 8 核及以上 |
| 内存 | 8 GB | 16 GB |
| 磁盘 | 50 GB 可用空间 | 200 GB SSD |
| Docker | 20.10 及以上 | 24.0 及以上 |
| Redis | 7.0 及以上 | 7.2 |

Redis 是必需依赖，用于存放会话状态、限流计数器和集群成员信息。
XR-2000 不再支持 Redis 6.x，因为用到了 7.0 引入的 Redis Functions 特性。

## 2. Docker 单机部署

### 2.1 拉取镜像

```bash
docker pull registry.example.com/xros/gateway:3.2.1
```

### 2.2 准备配置文件

```bash
mkdir -p /opt/xros/conf /opt/xros/logs
cp gateway.yaml /opt/xros/conf/
```

### 2.3 启动容器

```bash
docker run -d \
  --name xros-gateway \
  --restart unless-stopped \
  -p 8080:8080 \
  -p 9090:9090 \
  -v /opt/xros/conf:/etc/xros \
  -v /opt/xros/logs:/var/log/xros \
  -e XR_LICENSE_KEY=<你的授权码> \
  -e XR_REDIS_URL=redis://127.0.0.1:6379/0 \
  -e XR_LOG_LEVEL=info \
  registry.example.com/xros/gateway:3.2.1
```

服务默认监听 8080 端口提供管理 API 与 Web 控制台，9090 端口提供 Prometheus 指标。

### 2.4 环境变量清单

| 变量名 | 必填 | 默认值 | 说明 |
| --- | --- | --- | --- |
| XR_LICENSE_KEY | 是 | 无 | 授权码，缺失时服务拒绝启动 |
| XR_REDIS_URL | 是 | 无 | Redis 连接串 |
| XR_LOG_LEVEL | 否 | info | 日志级别 |
| XR_MAX_CONNECTIONS | 否 | 5000 | 最大并发连接数 |
| XR_UPSTREAM_TIMEOUT | 否 | 30 | 上游超时秒数 |
| XR_CLUSTER_ENABLED | 否 | false | 是否启用集群模式 |

环境变量的优先级高于配置文件，但低于通过 REST API 设置的值。

## 3. 健康检查与验证

服务提供两个探针端点：

- `GET /healthz` —— 存活探针，只检查进程是否运行，不检查依赖。返回 200 即正常。
- `GET /readyz` —— 就绪探针，会实际探测 Redis 连通性和 License 有效性。依赖不可用时返回 503。

部署完成后建议执行一次自检：

```bash
curl -s http://localhost:8080/healthz
curl -s http://localhost:8080/readyz
xros-cli version
```

如果 /readyz 返回 503，先用 `xros-cli doctor` 输出完整的依赖诊断报告。

## 4. 集群部署

XR-2000 支持集群部署，用于消除单点故障和横向扩展吞吐。

集群依赖 Redis 存放共享状态，所有节点必须连接到**同一个** Redis 实例或集群。
推荐的最小生产集群规模是 3 个节点，这样可以容忍 1 个节点故障而不影响服务。

集群模式下需要注意：

1. 所有节点的 XR_LICENSE_KEY 必须一致，否则节点之间无法互相认证。
2. 节点间需要开放 9091 端口用于 gossip 通信。
3. 集群成员的时钟偏差不能超过 5 秒，建议统一配置 NTP。
4. 会话状态在 Redis 中共享，所以客户端请求可以被任意节点处理，无需会话粘滞。

启动集群模式只需把 XR_CLUSTER_ENABLED 设为 true，并确保各节点能互相解析主机名。

## 5. 升级与回滚

小版本升级采用滚动方式，集群会逐个替换节点，期间服务不中断：

```bash
xros-cli cluster upgrade --image registry.example.com/xros/gateway:3.2.2 --rolling
```

如果升级后出现异常，可以用一条命令回滚到上一个版本：

```bash
xros-cli cluster rollback --to 3.2.1
```

回滚只恢复二进制版本，不会回滚配置。如果新版本改过配置结构，回滚前需要手动恢复配置备份。

## 6. 数据持久化

XR-2000 不存储业务数据，只持久化三类内容：日志、抓包文件、以及本地缓存的流控规则。
会话状态全部在 Redis 中，因此容器本身是无状态的，可以随时重建。

如果需要长期留存日志，建议把 `/var/log/xros` 挂载到外部存储，或配置日志转发到远端 syslog。
